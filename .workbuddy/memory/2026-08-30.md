## 后续修复：遗漏的 neo 组件变体（重要坑）

首次迁移只装了 `n*` 前缀的 registry 组件，导致 dropdown-menu / avatar / breadcrumb / collapsible 仍是标准 shadcn 版本，用了 neo 主题里不存在的 token（`bg-popover`、`bg-accent`、`text-muted-foreground`、`rounded-md` 等），表现为下拉菜单等图层没有背景色/圆角。

**关键教训**：neobrutalism registry 里 `nXXX.json` 和 `XXX.json` **都存在且都是 neo 版**。只有前几个组件有 `n` 前缀别名，像 `dropdown-menu`、`avatar`、`breadcrumb`、`collapsible` 只能走**不带前缀**的 URL（`separator` 是 404，但它只用 `bg-border`，可保留标准版）。所以正确做法是两类名字都探测一遍。

**更关键的排查手法**：Tailwind v4 对未在 `@theme` 中定义的 key **根本不生成 utility**，既不会在 CSS 里留下 `var(--popover)`，也不报错 —— 纯静默失效。所以"扫描编译 CSS 找未定义的 CSS 变量"这种方法**查不出来**。必须改为：
1. 在源码里 grep 旧 token（注意 `bg-secondary-background` 会误匹配 `bg-secondary`，要用负向预查 `(?!-)` 排除）；
2. 在编译产物里搜具体 class 选择器（如 `.bg-popover`）是否存在。

修复后剩余告警均已确认无害：`--radix-*`（Radix 运行时内联）、`--sidebar-width*` / `--skeleton-width`（SidebarProvider / SidebarMenuSkeleton 内联）、`--default-font-*-settings`（Tailwind 内部，带 fallback）。

## 字体：确认为 DM Sans

从上游 `src/app/layout.tsx` 确认 neobrutalism 官方用的是 **DM Sans**（`next/font/google`），且是用 `dmSans.className` 直接挂在 `<body>` 上，**不走 CSS 变量**。没有单独的标题字体族——标题靠 `--font-weight-heading` 的 `font-heading`（字重 700）区分。

据此把 `layout.tsx` 的 Geist 换成 DM Sans（`display: "swap"`, `adjustFontFallback: false`），并删掉 globals.css 里 `--font-sans` / `--font-mono` 两个映射（原本就没有任何地方消费 `font-sans` / `font-mono`，纯死代码）。

## 环境注意事项（本项目沙箱）

- **`/tmp` 不可写**：curl `-o /tmp/xxx` 会报 exit 23 / "No such file or directory"，且 `http=%{http_code}` 显示 000。所有临时文件必须写到项目目录内（如 `.tmp2/`），写完记得删。
- shadcn CLI 的 `--overwrite`/`-o` 生效，但输出会误报 "Skipped N files"，以文件内容为准，不要被误导。
- Git Bash 下 `cmd //c start "" <url>` 不会真正启动浏览器（只打印 cmd banner）。**用 PowerShell 的 `Start-Process <url>` 打开系统默认浏览器**。
- `agent-browser` 未安装（需下载约 500MB Chromium），纯预览场景直接用系统浏览器更快。被误导。
